# Core / Friday integration: SR6 natural attribute advancement

Implemented symbols (source only; root owns package publication):

- Canonical DTOs in `Chummer.Contracts/Characters/Sr6CareerAttributeAdvancementModels.cs`, exported by `Chummer.Engine.Contracts`: `Sr6CareerAttributeQuote`, `Sr6CareerAttributeCommand`, `Sr6CareerAttributeReceipt`, `Sr6CareerAttributeResult`, `Sr6CareerAttributeOutcome`, `Sr6CareerAttributeSchemas.QuoteV1`.
- Quote schema: `chummer.core.sr6-career-attribute-quote/v1`. No previously proposed generic attribute schemas were added. Commands carry the exact reviewed quote, operation GUID, unspecified-kind local expense date and explicit confirmation. Receipts carry that command, committed revision, Karma after, expense identity/amount and digest.
- Application seam: `ISr6CareerAttributeAdvancementService.Quote(ownerStamp, workspaceId, attributeId)`, `.Advance(ownerStamp, command)`, `.Lookup(ownerStamp, command)`. Attribute IDs are Core IDs such as `Body`, not XML codes such as `BOD`.
- `AddSr6Ruleset` registers `Sr6CareerAttributeAdvancementService`. The existing `FileWorkspaceStore` implements `ISr6CareerAttributeAtomicCommitCapability`. Unsupported stores return unavailable. The existing owner-context lease and workspace path lease protect execution.
- New optional auxiliary-state property: `WorkspaceDocumentAuxiliaryState.Sr6CareerAttributeReceipts`. Null is omitted on the wire. This is workspace history, not character XML. Receipt-bearing file records use format version 6. Pre-patch readers reject versions above 5 before rewriting; receipt-free records retain their existing version 4 (or retained-source version 5) format. No active-store migration was performed. The atomic writer preserves the committed receipt prefix. Continuation export/restore and adoption of receipt-bearing workspaces fail closed pending an SR6-aware continuation protocol. Byte-preserving file backups retain the fence. Rollback to older binaries cannot open or write receipt-bearing records; removing receipts or lowering the version is not a supported rollback. Unreleased receipt-bearing version-4/5 records are rejected rather than silently adopted.

Friday must obtain a quote through the owner-bound service, display `NaturalRating`, `TargetNaturalRating`, `NaturalMaximum`, `AugmentationBonus`/`EffectiveRating`, `KarmaCost`, blockers and provenance. Only enable confirmation for `Available` with `Quote.CanAdvance`. Submit the exact quote and one stable operation ID. Do not reconstruct a quote, infer natural allocation from totalvalue, or mutate/debit shared XML.

`Applied` and `Replayed` both carry the durable receipt. Refresh the workspace after either. A stale workspace/rule binding returns `Conflict` and needs a fresh quote and confirmation. On unavailable/unknown transport outcome, retain the original command and operation ID: use `Lookup` or retry that exact command. `NotFound` is not permission to generate a replacement identity. `IdempotencyConflict` reserves an existing identity for different or imported history. Unavailable stores/rules do not advertise an executable operation.

Both raw `CharacterSectionService` attribute projection paths now keep SR6 saved Karma allocation separate from effective totals, use the natural XML ceiling for the display allocation range, and expose upgrade cost -1 / eligibility false. XML alone cannot certify advancement authority. SR5 projection behavior is unchanged. Friday must overlay advancement from this service; no UI changes or Friday wiring were performed here.

Supported authority is deliberately bounded to Core-finalized SR6 Priority/Sum-to-Ten/Point-Buy archives whose original creation decisions can still be re-evaluated under the current Core environment. Eight ordinary physical/mental attributes are supported. Approved creation Exceptional Attribute limits and permanent adept attribute bonuses are derived by the existing creation rules, never matched by display name or accepted from XML maxima. Natural purchases are replayed from the durable ledger. The XML native totalvalue convention remains natural; sr6creation/passiveattributes carries effective values and supported derived values are refreshed on purchase.

Imports without that archive, special attributes, other post-Creation XML edits outside the bounded accepted fields, later custom effects, and authority that no longer re-evaluates return explicit unavailable. Arbitrary Career quality/amend/augmentation authoring and a general effect resolver are not implemented. This operation is not a claim of universal SR6 advancement support. Existing SR5 attribute rules/services are untouched.
